# Phase 3B：iPhoneから使う都市編集（v0.3.1）

PCでPythonサーバーを動かし、ブラウザから既存都市を選択・編集します。Web専用の生成器はなく、Phase 3Aの `prepare_edit` / `apply_edit` / `undo_edit` を共有します。外部の地図サービスやJavaScript CDNへの通信は不要です。

Phase 4の `--paper-config` 使用時は、Webの直接承認/Undoを無効化し、同じ計画を `/city review` でゲーム内へ渡します。ワールド完了後に地図を自動更新します。[Paper連携手順](PAPER.md)。以下のWeb単独承認手順はPaper設定なしの場合です。

## PCで起動する

READMEの環境構築後、リポジトリ内で実行します。

```bash
python -m pip install -e .
citygen web --project examples/managed-city/project.json \
  --state-dir output/web-session --parser rules
```

ターミナルに表示された接続URLをブラウザで開きます。`#token=...` を含むURL全体が必要です。既定は `127.0.0.1:8765` で、PC外からは接続できません。ポート変更は `--port 8766`。終了はCtrl+Cです。

`--parser rules` はAPI通信なし。`auto`（既定）は環境変数 `OPENAI_API_KEY` があればLLMを利用し、なければ限定日本語ルールです。キーはPC側だけで設定し、Web画面に入力しません。

## 同じWi-FiのiPhoneから接続する

Windowsの `ipconfig` でWi-Fi/LANアダプターのプライベートIPv4を確認し、PCをそのアドレスで起動します。以下のアドレスは例なので置き換えてください。

```bash
citygen web --project examples/managed-city/project.json \
  --state-dir output/iphone-session --parser rules \
  --lan --host 192.168.1.20
```

PowerShellでは1行にまとめて実行してください。同じネットワークのiPhone Safariへ表示されたURL全体を渡して開きます。Windowsファイアウォールの確認が出た場合は、信頼するプライベートネットワークに限ってPythonの受信を許可します。ルーターのポート開放は不要です。

`--lan` だけでは公開されません。明示した10.x / 172.16〜31.x / 192.168.xの実アドレスにだけbindします。`0.0.0.0`、公開IP、IPv6の全インターフェース指定は拒否します。

この版は信頼する家庭内LAN向けのHTTPです。HTTPS、ユーザー別権限、公開サービス用認証はありません。接続URLを持つ端末は同じ都市を編集できます。リバースプロキシやトンネルによるインターネット公開は対象外です。

## 地図から計画・承認・Undo

1. 地図は1本指でドラッグ、2本指でピンチズーム。「＋」「−」「全体」でも操作できます。PCはホイールにも対応します。
2. 「選択・移動」で建物または地区をタップします。区・地区のプルダウンでも選択できます。建物は建物ID、地区は登録された地区IDが対象になります。
3. 「位置を指定」でタップしてX/Zを指定、「範囲を指定」でドラッグして矩形を指定します。区/地区と組み合わせた条件は交差になります。「選択を解除」で対象をリセットできます。
4. 日本語で指示し「計画をつくる」を押します。例：`中央区の空き地にコンビニを作って`。この時点では都市は変わりません。
5. 変更前後、追加/変更件数、対象・衝突検査・補完条件を確認します。「地図で変更箇所を見る」で提案をピンクの枠で拡大表示します。計画JSONや枠付き比較画像も保存できます。
6. 「承認して建築する」で新しいprojectとschematicを保存します。「見送る」は何も建築しません。指示や選択を変更すると古いプレビューは閉じ、新しい計画が必要になります。
7. 「project.json」「Minecraft .schem」で現在の状態をダウンロードできます。
8. 「直前の建築を取り消す」→「承認してUndo」で変更前へ戻した新しい状態を保存します。複数回の編集は逆順でUndoできます。

建物を選択した場合は `指定した建物の外観をもっと現代的にして`、矩形の場合は `この範囲に公園を作って`、地区の場合は `この地区に住宅を5棟追加して` などが使えます。選択がない「ここ」は確認要求になります。数量を含む指定の一部だけを建築しません。詳細な文法・登録済み空地を置換しない制限は [EDITING.md](EDITING.md) を参照してください。

外観変更は建物IDと形状を維持し、追加は新しいIDと敷地を登録します。道路・河川・鉄道を変更する指示はまだ扱いません。

## 保存・再起動・競合

元の `--project` は読み込み専用です。Web用の独立した作業コピーを `--state-dir` に作り、承認のたびに新しいスナップショットと編集履歴を残します。現在状態を指す `session.json` は書き込み完了後に原子的に更新します。

続きから再開する場合は、同じ保存先だけを指定し、`--project` を省略します。

```bash
citygen web --state-dir output/web-session --parser rules
```

LANで再開するときも `--lan --host <PCのIP>` を指定します。再起動で接続トークンは変わるため、新しく表示されたURLを開いてください。URLのトークンは読み取り後アドレスバーから除去し、ブラウザのタブ用セッションストレージに保持します。

同じ保存先で2台目のサーバーを起動すると `server.lock` により拒否します。強制終了した場合はサーバープロセスが動いていないことを確認してから、その保存先の `server.lock` だけを手動で取り除きます。project、履歴、session.jsonを削除する必要はありません。

古い画面からの承認は都市のリビジョン不一致として拒否します。「更新」を押して確認してください。同時の処理は1件だけで、処理中の他リクエストは409を返します。接続が切れても既に完了した建築は保存されるため、再接続時はまず地図を更新してください。

承認前のレビューは最新20件を参照できます。保存済みのスナップショットは自動削除しません。長期間使う場合は停止後に保存先全体をバックアップしてください。ディスクが満杯になると操作は失敗しますが、完了前に現在状態へ切り替えません。

## アクセス制限

- API・地図画像・都市ファイルは起動ごとのランダムトークンが必要です。外部サイトのOrigin、不正Hostは拒否し、CORSは開放しません。
- Webからファイルパス、OSコマンド、APIキーを指定するAPIはありません。起動時に指定した1プロジェクトだけを扱います。
- ダウンロードはサーバーが作ったIDと許可済みファイル名に限定し、パストラバーサルやシンボリックリンク経由の取得を拒否します。
- 入力JSONは16KiB、指示は2000文字、追加棟数は既存エンジンの1〜10棟制限です。HTTP接続処理は最大8本、建築処理は同時1件です。
- 元プロジェクト・衝突・接道・承認IDの再検証とUndo検証はPhase 3Aと共通です。再起動したWebセッションは保存された現在projectのダイジェストも確認します。

## 検証と制限

PythonのHTTP統合テストに加えて、Playwrightから実際のWebサーバーを操作するテストを用意しています。

```bash
python -m pip install -e ".[dev,browser]"
python -m playwright install chromium webkit
pytest -q
python scripts/check_web_browser.py --browser chromium --output output/browser-chromium
python scripts/check_web_browser.py --browser webkit --output output/browser-webkit
```

Linuxでブラウザの共有ライブラリが不足する場合、管理可能な環境で `python -m playwright install --with-deps chromium webkit` を使用します。通常のWebアプリ起動にPlaywright・Node.js・ブラウザテスト用ライブラリは不要です。

テストはiPhoneサイズの画面で選択・位置/矩形・ズーム・計画・承認・ダウンロード・Undo、デスクトップ表示を検証し、スクリーンショットと結果JSONを出力します。Chromiumでは2点タッチのピンチも自動検証します。WebKitはSafariと同系統のエンジンですが、実iPhone Safariでの操作・ダウンロード確認の代わりではありません。

8GB・HDDのWindows実機負荷、実iPhone、実OpenAI API、Minecraft/WorldEdit実機は未検証です。単一都市・単一利用者向けで、都市全体を再建築します。複数ユーザーの権限管理、Web上での都市ファイルアップロード、Paper/Bedrock、ゲーム内差分反映、大規模チャンク処理は後続段階です。
